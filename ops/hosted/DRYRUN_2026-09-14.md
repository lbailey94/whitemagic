# Hosted-lane dry-run — local ghost of the kit (2026-09-14)

**Method:** the full chain (authd → `wm serve --transport sse --readonly`)
ghosted on scratch ports (18889 upstream, 18890 gateway — the machine's
18789–18798 belong to live units) with `WM_LANDLOCK=1`, a seeded scratch
store, and issued free keys. Caddy is not installed locally; its config was
reviewed statically (`/health`, server-card, `/mcp` → authd, default 404) and
must be validated on the box.

## Bugs found (fixed in this commit)

1. **HTTP framing hang.** `401`, `429`, and upstream-error responses were sent
   without `Content-Length`, so HTTP/1.1 clients (and the Caddy hop) waited for
   a body that never came. Fixed in `authd.py` (explicit `Content-Length`,
   error body length).
2. **Landlock skipped entirely under `--readonly`** (`wm.rs`): the requested
   ruleset was never applied, failing the acceptance criterion "Landlock report
   says enforced". Fixed: the ruleset now applies in readonly mode; only the
   on-disk report write is suppressed (served in-memory via `/status`), so a
   frozen store is still never written to.
3. **Keyless discovery missing.** authd gated every request, so MCP directory
   probes and pre-purchase browsing would get 401 — the "free discovery"
   invariant in `X402_DESIGN.md`. Fixed: `initialize`,
   `notifications/initialized`, `tools/list`, `ping` pass without a key under a
   global daily cap (`--anon-daily-cap`, default 2000); `tools/call` still
   requires a key.

## Repro (local)

```bash
D=/tmp/wm-dry; mkdir -p $D/state $D/store
WM_HOSTED_STATE=$D/state ops/hosted/issue-free-key.sh beta 50
WM_LANDLOCK=1 wm serve --transport sse --bind 127.0.0.1:18889 --readonly \
  --rate-limit 600 --max-requests 100000 --store $D/store &
python3 ops/hosted/authd.py --listen 127.0.0.1:18890 \
  --upstream http://127.0.0.1:18889 --state $D/state --anon-daily-cap 2000 &
curl -s -X POST 127.0.0.1:18890/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'
```
