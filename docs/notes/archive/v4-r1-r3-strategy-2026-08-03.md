## 1. Objective

Implement the three critical-path phases that transform v4 from an AI agent runtime into a real-time cognitive substrate:

- **R1**: Reflex tier — <100µs dispatch with zero heap allocation
- **R2**: Multi-timescale event bus — 5-tier hierarchical control loops
- **R3**: Global workspace bus — salience-based multi-objective arbitration

These three phases are the existential foundation. Without R1, v4 cannot serve any real-time domain. Without R2, reflex and cognitive tiers cannot coordinate. Without R3, multiple objectives cannot arbitrate.

## 2. Phase R1: Reflex Tier (`wm-reflex`)

### 2.1 Design

The reflex tier bypasses the entire cognitive pipeline (NLU, Dharma, rate limiter, circuit breaker, karma) and executes via a pre-compiled dispatch table with direct function pointers. The only safety check is a single bitmask AND against a pre-compiled allowlist.

**Key constraints:**
- No trait objects (`dyn Tool`) — direct function pointers
- No heap allocation — stack-allocated `ReflexArgs` / `ReflexOutput`
- No serde — fixed-layout structs with `#[repr(C)]`
- No governance pipeline — bitmask safety check only
- Reflex tools cannot call cognitive tools (no upward calls)
- Cognitive tools can register reflex handlers (downward registration)
- Feature-gated: `#[cfg(feature = "realtime")]`

### 2.2 Types

```rust
// Stack-allocated argument buffer (256 bytes max)
#[repr(C)]
pub struct ReflexArgs {
    pub sensor_id: u16,
    pub timestamp_ns: u64,
    pub payload: [u8; 240],  // Fixed payload buffer
    pub payload_len: u8,
}

// Stack-allocated output (128 bytes max)
#[repr(C)]
pub struct ReflexOutput {
    pub actuator_id: u16,
    pub command: ReflexCommand,
    pub priority: u8,
    pub payload: [u8; 120],
    pub payload_len: u8,
}

// Safety bitmask — each bit is a capability allowlist
pub type SafetyMask = u32;
```

### 2.3 Dispatch Table

```rust
pub struct ReflexDispatchTable {
    handlers: [Option<ReflexHandler>; 256],  // Indexed by reflex_id (u8)
    safety_mask: SafetyMask,
}

pub type ReflexHandler = fn(&ReflexArgs) -> Result<ReflexOutput, ReflexError>;
```

Dispatch is a single array index + bitmask AND + function call. No hash lookup, no trait dispatch, no allocation.

### 2.4 Built-in Reflexes

| ID | Name | Trigger | Action |
|----|------|---------|--------|
| 0 | `e_stop` | Any sensor | Halt all actuators |
| 1 | `collision_avoid` | Proximity sensor | Brake/redirect |
| 2 | `thermal_limit` | Temperature sensor | Reduce power |
| 3 | `frequency_deviation` | PMU sensor | Trigger correction |
| 4 | `beam_instability` | Beam position monitor | Beam dump |
| 5 | `pwave_detect` | Seismometer | Issue alert |
| 6 | `packet_drop` | Network packet | Drop + log |
| 7 | `qec_correct` | Syndrome measurement | Apply correction |

### 2.5 Benchmark Target

<100µs end-to-end for reflex dispatch (array index + bitmask + fn call). Expected: <1µs.

## 3. Phase R2: Multi-Timescale Event Bus (`wm-timescale`)

### 3.1 Design

Five tier loops, each running as a tokio task with `tokio::time::timeout` budget enforcement. Hooks are registered per-tier and executed within the tier's time budget. If a hook exceeds its budget, it's killed and a fallback fires.

### 3.2 Tiers

| Tier | Name | Period | Budget | Brain-wave Active |
|------|------|--------|--------|-------------------|
| 0 | Reflex | 100µs–10ms | 10ms hard | Gamma (on-demand in Beta) |
| 1 | Reactive | 10ms–1s | 1s | Gamma, Beta |
| 2 | Planning | 1s–30s | 30s | Gamma, Beta |
| 3 | Consolidation | 30s–1hr | 1hr | Theta (also Gamma) |
| 4 | Evolutionary | 1hr+ | — | Delta heartbeat |

### 3.3 Hook Registration

```rust
pub struct TimescaleBus {
    hooks: [Vec<Hook>; 5],  // One vec per tier
}

pub struct Hook {
    id: u64,
    name: String,
    callback: Box<dyn Fn() -> HookResult + Send + Sync>,
    fallback: Option<Box<dyn Fn() + Send + Sync>>,
    priority: u8,
}

pub enum HookResult {
    Complete,
    NeedsMoreTime,
    Error(String),
}
```

### 3.4 Brain-Wave Integration

The timescale bus queries the current brain-wave state to determine which tiers are active:
- **Gamma**: All tiers active
- **Beta**: Tiers 1–4 active, tier 0 on-demand
- **Alpha**: Tiers 1–3 active
- **Theta**: Tier 3 active (consolidation only)
- **Delta**: Tier 4 heartbeat only (1hr interval)

### 3.5 Budget Enforcement

Each tier loop uses `tokio::time::timeout`:
```rust
match tokio::time::timeout(budget, hook.callback()).await {
    Ok(result) => { /* process result */ },
    Err(_) => {
        // Budget exceeded — fire fallback
        if let Some(fb) = &hook.fallback { fb(); }
    }
}
```

## 4. Phase R3: Global Workspace Bus (`wm-workspace`)

### 4.1 Design

A publish/subscribe event bus where all cognitive cores publish state events. The workspace arbitrates attention: whichever core has the highest salience score wins the "spotlight" for the next decision cycle.

### 4.2 Salience Scoring

**Decision**: Use the multiplicative formula from v2 (urgency × novelty × confidence) rather than the additive formula from the roadmap. Rationale: multiplicative scoring better captures the intuition that an event with zero urgency OR zero novelty OR zero confidence should not win the spotlight, regardless of how high the other dimensions are.

```rust
pub struct Salience {
    pub urgency: f32,      // 0.0–1.0
    pub novelty: f32,      // 0.0–1.0
    pub confidence: f32,   // 0.0–1.0
}

impl Salience {
    pub fn composite(&self) -> f32 {
        self.urgency * self.novelty * self.confidence
    }
}
```

### 4.3 Event Types

```rust
pub enum EventType {
    Error,
    Reward,
    AttentionRequest,
    NovelDetection,
    ThresholdCrossing,
    DriveUpdate,
    SafetyAlert,
}

pub struct WorkspaceEvent {
    pub core: CoreId,
    pub event_type: EventType,
    pub salience: Salience,
    pub payload: serde_json::Value,
    pub timestamp: Instant,
}
```

### 4.4 Spotlight Mechanism

The workspace maintains a time-decayed spotlight using v2's formula: `spotlight_strength = 0.5^(age/half_life)`. The half_life defaults to 5 seconds. High-salience events (>0.8 composite) can preempt the current spotlight immediately.

### 4.5 Event Bus

Uses `tokio::sync::broadcast` channel for multiple subscribers. The workspace tracks:
- Current spotlight (which core is "in focus")
- Recent event backlog (ring buffer, last 256 events)
- Per-core salience statistics

### 4.6 MCP Tools

- `workspace.spotlight` — query current attention state
- `workspace.events` — query recent event backlog

## 7. Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Salience formula | Multiplicative (v2) | Zero in any dimension → zero spotlight |
| Reflex args size | 256 bytes | Fits on stack, covers sensor frames |
| Reflex dispatch | Array index by u8 ID | O(1), no hash lookup |
| Timescale bus | tokio tasks per tier | Natural async, budget via timeout |
| Workspace channel | tokio::sync::broadcast | Multiple subscribers, lossy on slow consumers |
| Spotlight decay | 0.5^(age/half_life) | v2 proven formula, exponential decay |
| `#![forbid(unsafe_code)]` | Yes, all three crates | Consistent with workspace policy |
