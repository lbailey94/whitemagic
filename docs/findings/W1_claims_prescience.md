## Adversarial cases

1. **Destructive sync:** a curated seed overwrite must not delete independently recorded ledger rows
   (Gen1's `source_ref`-keyed delete would erase oracle/time-estimate claims on any CLI run —
   `temporal_db.py:164-171`).
2. **Degenerate calibration:** a ledger of all-validated claims yields BS/BSS with no falsified
   outcome; expired handling (summary excludes expired, TZPF counts it as 0) and post-hoc
   `behavioral_confidence` (ex-ante vs ex-post) must be pinned before any calibration claim is quoted.
3. **Free-text validation:** `validation_ref` is uncited and unchecked; NRS scores org *names inside
   a string* (`tzpf.py:409-449`), so a name-rich sentence inflates a metric without an event.
4. **Points not reproducible:** hand-entered `points` diverge from `floor(lead_weeks)` in 6/52 rows
   (fractional values; round-ups) — a totals claim cannot be re-derived from the dates alone.
5. **Oracle confound:** `resolve_oracle_claim` decides status from `outcome_positive` while
   `action_taken` is stored in the same row (`temporal_db.py:599-617`) — followed-guidance and
   outcome are not separable in the score.

## Ablation ideas

- Diff the DB before/after one `seed_validated_claims()` on a DB containing an oracle + a depth-gauge
  row; expect removal of both (measures the sync hazard).
- Recompute points as `floor(lead_weeks)` for all 52; quantify total divergence (6 rows, −5.7 pts here
  under stored sum; header itself already drifts).
- Include `expired` as outcome 0 in BS/BSS; measure the gap shift (52 vs 53 closed items in the YAML
  set).
- Null the NRS org-regex (`tzpf.py:409-442`) and set `actions_taken=None`; DFI/Brier must be
  unchanged while NRS collapses and PI→0 — both are string/manual inputs, not evidence.
